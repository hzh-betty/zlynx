## 实施范围

- Buffer 在 8 MiB 以下仍翻倍，之后从每次加 1 MiB 改为增长 50%，截断到
  512 MiB。一次完整记录仍先 reserve，失败不会留下半条记录，safe 仍固定 2 MiB。
  双缓冲、已有 prefault 和内存所有权机制保留。删除不再使用的增量常量。
- AsyncLooper 只在生产缓冲从小于 64 KiB 越过阈值时通知消费者，并在解开队列锁后
  notify。等待谓词仍由队列锁保护；消费者交换后的队列若已超过阈值，会直接继续处理。
  flush 与 stop 的通知和完成屏障保留，默认等待时间保留。
- FileSink 新增三参数构造重载，RollBySizeSink 新增五参数构造重载，支持
  `FileBufferMode::BUFFERED`。旧构造函数仍无缓冲，避免改变即时写错误与可见性契约。
  新模式使用标准库缓冲，不承诺固定缓冲大小；auto_flush、共享 sink 锁、逐条滚动、
  多 sink 继续尝试和首个异常传播保留。

未改变公开对象成员、虚函数、旧构造符号、SONAME 或最低 C++ 标准。
同一工具链下 LogSink/FileSink/RollBySizeSink/AsyncLogger 的 sizeof 分别仍为
8/600/664/144 字节；原有 zlog 导出符号全部保留，仅新增构造重载，见 `abi-check.json`。
这项检查不代表不同标准库或工具链之间的 ABI 保证。

## 复测方法

Clang 21.1.8；根工程 Release `-O3 -DNDEBUG -g`，shared library，C++17，
coverage/Sanitizer OFF，默认 zmalloc override ON，Linux ext4 文件路径。
使用原归档的公开接口 bench_probe，只增加 buffered sink 选项及相同内容校验，
同一个可执行程序通过 LD_LIBRARY_PATH 选择冻结的基线或候选库。
正式区间包含排空与 flush；预热每线程 5,000 条，线程创建、校验和 close 不计时。
固定正文、full pattern、异步 100 ms 等参数与原分析一致。

最终共 450 次随机交错运行：基线 165 次、最终默认模式 165 次、显式缓冲 120 次，
每格重复 5 次；所有样本校验通过，文件案例核验条数与正文，null 案例核验调用条数。
覆盖 1/2/4/8/16 线程，另测 32/1024/4096 字节。
独立扩容对照 36 次，逐字节校验；strace 6 次，校验通过但其耗时不作为吞吐数据。
本任务在正式性能测量期间未启动构建、Sanitizer 或 profiler。其他会话和宿主负载
未全程采集；结束时还存在其他模块的优化 worktree，无法确认它们是否与测量重叠。

本轮波动明显，连同步 null 等基本未改变的控制场景也有漂移。CV 是标准差/均值，
不能把小幅中位数差异当作稳定收益；WSL2 数值不外推到原生 Linux、真实业务 QPS、
物理磁盘吞吐或生产 P99。flush 没有增加 fsync。

## 结果

扩容探针逐次写入 1 MiB，每格 3 次中位数；计时包含扩容、prefault 和写入：

| 写入 MiB | 原版本 ms | 最终 ms | 扩容次数 | 最终容量 MiB |
|---:|---:|---:|---:|---:|
| 32 | 233.385 | 47.031 | 26 → 6 | 40.500 |
| 64 | 975.753 | 122.766 | 58 → 8 | 91.125 |
| 128 | 4066.910 | 184.519 | 122 → 9 | 136.688 |

128 MiB 隔离扩容约快 22 倍。这不是日志吞吐的 22 倍收益。
初始两倍增长候选的该探针更快，但大消息对照占用较高；最终使用 1.5 倍控制
每次扩容的额外预留量，仍维持摊销线性的复制量。

128 字节正文、500,000 条正式文件记录。每格是吞吐中位数（百万条/秒）/ CV：

| 模式 / 线程 | 原版本 | 最终默认无缓冲 | 最终显式缓冲 |
|---|---:|---:|---:|
| sync / 1 | 1.821 / 7.9% | 1.053 / 51.1% | 6.903 / 40.8% |
| sync / 4 | 0.490 / 29.2% | 0.352 / 19.7% | 1.863 / 76.7% |
| sync / 16 | 0.299 / 8.2% | 0.322 / 2.7% | 1.191 / 1.5% |
| safe / 1 | 2.270 / 19.9% | 2.302 / 12.2% | 9.368 / 36.5% |
| safe / 4 | 2.191 / 8.3% | 2.280 / 16.3% | 5.605 / 12.2% |
| safe / 16 | 1.831 / 10.3% | 1.820 / 34.2% | 4.096 / 25.0% |
| unsafe / 1 | 2.364 / 9.8% | 2.436 / 17.7% | 9.668 / 2.9% |
| unsafe / 4 | 2.118 / 6.3% | 2.271 / 13.7% | 4.989 / 28.2% |
| unsafe / 16 | 1.631 / 32.7% | 2.026 / 15.1% | 5.204 / 7.4% |

例如最终库的同步 16 线程，启用缓冲后从 0.322 到 1.191 M/s，约 3.7 倍；
两组 CV 分别为 2.7% / 1.5%。safe 4 线程从 2.280 到 5.605 M/s，约 2.5 倍，
CV 16.3% / 12.2%。这些是本机合成负载的对照，不是所有日志大小的统一收益。

4 线程、100,000 正式 + 20,000 预热记录的 strace 中，三种模式的无缓冲 writev
均为 120,000 次；缓冲后均为 2,352 次，减少约 98%。另有少量 write，包括 JSON
结果输出与流刷新；表格中的 syscall 耗时受 ptrace 影响，不用于性能收益计算。

队列通知改动的最终默认 null/full 对照中，safe 4 线程吞吐为 3.688 → 6.247 M/s，
CV 6.7% / 13.5%。unsafe 16 线程为 3.299 → 3.321 M/s，CV 21.2% / 20.3%，
不能声称该场景获得稳定收益。没有重新采集 perf 的自旋 CPU 占比，自旋争用仍存在。

unsafe 默认无缓冲、4 线程的代价必须单独看：

| 正文 bytes | 吞吐 M/s（原 → 最终） | VmHWM MiB（原 → 最终） |
|---:|---:|---:|
| 128 | 2.118 → 2.271 | 50.2 → 69.2 |
| 1024 | 0.842 → 0.682 | 58.2 → 148.0 |
| 4096 | 0.350 → 0.294 | 58.4 → 148.1 |

默认 unsafe 的 1024/4096 字节场景没有证明吞吐收益，且本轮中位数较低；
CV 约 20–30%，无法精确量化回退幅度。几何增长与队列积压使峰值驻留内存增加，
4096 字节场景约从 58.4 到 148.1 MiB。显式缓冲也没有为这个大消息场景带来稳定收益。
需要限制驻留内存时应继续使用 safe；unsafe 保留扩容和峰值容量，不能称为整体低内存优化。
完整吞吐、调用采样分位数、CPU/墙钟和 VmHWM 在本轮 `summary.csv`。

## 独立候选与回退

按顺序冻结并测量了增长、通知、锁策略候选，原始数据为 `compare-*.jsonl`。
std::mutex + condition_variable 改善部分文件场景，但在配对对照中将 16 线程 null
吞吐降低约 39–45%，因此撤回。自旋快速路径先 relaxed load 再 exchange 的候选
也出现约 21–25% 的 null 吞吐回退，因此撤回。最终仍使用原自旋锁与 acquire/release。
这些阶段间绝对值存在漂移，不能相减归因，也没有引入无锁队列、线程池、对象池或新依赖。

## 使用与复现

```cpp
builder.build_logger_sink<zlog::FileSink>(
    "app.log", false, zlog::FileBufferMode::BUFFERED);
// 或按单条记录滚动：
builder.build_logger_sink<zlog::RollBySizeSink>(
    "logs/app", 10 * 1024 * 1024, false, 10, zlog::FileBufferMode::BUFFERED);
```

缓冲可能推迟小记录可见性和写错误。显式 flush()/close() 用于交付与错误处理；
auto_flush=true 仍逐条刷新。旧调用无需迁移，保持原无缓冲行为。
